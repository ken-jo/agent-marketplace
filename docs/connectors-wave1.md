# Connector wave 1

The ten additions are Jira, Confluence, Trello, Todoist, Airtable, Obsidian, Figma, YouTube, Google Workspace and Microsoft 365. With the existing Slack and GitLab connectors, the owner's selection totals twelve. Jira and Confluence count separately; the existing Atlassian package is a skill. The research document's “14 apps” heading and optional Discord entry do not describe this selection: the owner dropped Discord on October 17. The old Slack/GitLab community packages are excluded as duplicates. Existing packages remain unchanged, and no selected upstream was excluded for licensing.

Six npm runtimes commit an exact top-level version, its registry tarball URL and SHA-512 SRI, plus a version-3 package lock with an exact version, HTTPS registry URL and SHA-512 integrity for every transitive package. The downloaded top-level tarballs were checked against both SRI and SHA-256 and contained MIT licences; their hashes and licence digests are in the inventories. Todoist, Airtable, YouTube and Microsoft supply matching registry gitHead mappings. Trello and Figma supply none: the inspected tarball hashes are the artifact identity, not an assumed source-to-build mapping.

Trello's original tarball embeds its SDK, so it cannot share the registration filter's SDK instance. Its executable is instead the committed build of the reviewed source SHA, produced with Bun 1.3.14 and external dependencies. The inventory records the build hash, source commit, source-archive digest and command. The original exact npm package remains the dependency-closure root; its embedded executable is not run. CI rebuilds Trello and requires byte equality with the committed artifact. Its MIT notice accompanies the build.

The four Python runtimes commit complete version-and-hash locks. Jira and Confluence run the inspected, SHA-256-locked PyPI wheel. Google Workspace and Obsidian run committed, hashed wheels built from their reviewed Git SHAs, avoiding install-time Git builds or build-dependency resolution. CI compares every wheel payload file and its licence with that source commit. The wheels' metadata is hash-bound too; these builds are not claimed to be reproducible byte-for-byte from a later build environment. All Python dependencies have exact versions and SHA-256 artifact hashes, and only wheels can be installed. Python 3.12.12 is selected explicitly.

The packaged bootstrap applies the same inventory-before-execution pattern used by the repository's vendor verifier. It checks runtime inputs, installs into a fresh private directory under Ave's data directory, then checks the inputs again. npm uses ci with lifecycle scripts disabled and no audit/funding requests; uv uses pip sync with required hashes and binary-only artifacts. There is no install-time dependency update, npx resolution or uvx resolution. The [bootstrap](../tools/connector-runtime.mjs) gives package-manager subprocesses a small credential-free environment, empty npm user/global configuration, and no host token or Node injection flags. A changed dependency artifact fails integrity checking. Runtime directories are removed on normal process exit; package-manager caches contain only public dependency artifacts.

## Prerequisites and host runtime boundary

All ten packaged launchers declare macOS/Linux eligibility and require Node.js 24+ on Ave's PATH. The six npm servers also require npm; the four Python servers require uv. Set AVE_CONNECTOR_NPM or AVE_CONNECTOR_UV to an absolute executable path if those tools are not on the app's PATH. These are nonsecret server environment settings. Missing prerequisites fail with a checked, constant message before installation; the shell wrapper needs no dirname utility. Each descriptor sets AVE_CONNECTOR_DATA_DIR to $DATA_DIR/locked-runtime, which Ave expands to an absolute writable package-data path. For manual execution, set AVE_CONNECTOR_DATA_DIR to your own absolute scratch directory; it is required and contains no credential configuration.

Ave v0.14.0 rewrites only a direct uvx command to its [bundled uv runtime](https://github.com/ken-jo/ave/blob/v0.14.0/src/mcp/mcp-client.ts). Its marketplace normalizer does not retain packaged bootstrap files for that launcher form and rejects a $PLUGIN_DIR reference there; the direct uvx form also accepts only an exact registry package. It cannot express this packaged, hash-locked bootstrap. Therefore these presets use the explicit checked prerequisite route, with no ambient uvx call hidden inside a shell script. AVE_CONNECTOR_UV can point to Ave's already-extracted bundled binary: the [host resolver](https://github.com/ken-jo/ave/blob/v0.14.0/src/main/uv-runtime.ts) keeps it under the Ave home runtime/uv/<target>/<binary-sha256>/uv directory. The bootstrap does not guess a private app path or extract another binary. Minimal-PATH tests cover missing Node and missing uv, including a PATH containing only Node.

## Credentials and tool access

Install the MCP package in Ave, then enter credentials only through its secret prompt. Site URLs, account usernames and runtime paths belong in nonsecret server environment settings. No credentials enter arguments, package files, .env files or token caches. All declared secret strings and decoded JSON fields reject NUL, other control/format characters and Unicode line separators before subprocess creation. Synchronous and asynchronous launch failures use constant messages, never raw process errors containing arguments or environment values.

The [v0.14.0 package schema](https://github.com/ken-jo/ave/blob/v0.14.0/schemas/marketplace/package.schema.json) and [stdio server configuration](https://github.com/ken-jo/ave/blob/v0.14.0/src/mcp/types.ts) have no package tool allow/deny list. These presets supply it through adapters: the npm adapter filters SDK registration before opening stdio, Obsidian filters its handler registry, and Google uses its native disabled-tool option. A blocked tool is unregistered, so direct calls fail as well as being absent from discovery. The npm and Obsidian allowlists reject unknown names; Google instead uses its pinned upstream core/read-only selection plus an explicit local-tool denylist, so a pin update must recheck its selected names. The [registration adapter](../tools/connector-policy.mjs) and [protocol checks](../tools/connector-smoke.mjs) make this boundary inspectable. The service read-only flags remain enabled for Jira, Confluence, Google and Microsoft.

Both write controls default to false in every descriptor. To opt in, set AVE_CONNECTOR_ALLOW_WRITES=true for the reviewed Trello/Todoist/Airtable/Obsidian service-mutation sets, or AVE_CONNECTOR_ALLOW_LOCAL_WRITES=true for the reviewed Trello/Figma/Google/Microsoft local-download/export sets. Only the exact values true and false are accepted. These controls do not enable unknown tools, Microsoft's auth/account tools, Google's interactive login, or Trello's native configuration/repair tools. Jira/Confluence local attachment tools retain the explicitly disclosed behavior in the table. Application caches and dependency installation are local writes regardless of tool policy; “read-only tools” is not a filesystem sandbox claim.

Use a read-scoped Trello token and an Airtable PAT limited to schema.bases:read, data.records:read and the needed bases by default. The adapter enforces the default tool boundary independently of those token scopes. Enabling write tools does not expand the token's permissions.

Trello's secret is one JSON object with exactly apiKey and token fields, for example {"apiKey":"<API key>","token":"<read-scoped token>"}. The bootstrap validates it, splits it in memory into upstream environment variables and removes the combined value before loading the server.

Google's secret is one JSON object with exactly email, client_id, client_secret and refresh_token. Obtain offline credentials using your own desktop OAuth client with gmail.readonly, calendar.readonly, drive.readonly, documents.readonly and spreadsheets.readonly scopes under https://www.googleapis.com/auth/. The [Google adapter](../mcp/google-workspace-mcp/server/launch.py) binds the memory-only CredentialStore to that email, blocks OAuth state creation, disables start_google_auth and disables file logging. Refreshed access tokens remain in memory. If the refresh token rotates or is revoked, obtain fresh offline consent and replace the secret in Ave before the next launch. The host descriptor cannot receive a rotated token back from the server. Interactive OAuth onboarding inside this preset is unavailable.

Microsoft accepts an existing delegated Graph access token. Replace it in Ave when it expires; this preset cannot refresh it or start interactive OAuth. Its registration filter permanently removes login, logout, verify-login, list-accounts, select-account and remove-account, even with both write opt-ins enabled. The [external cache adapter](../mcp/ms-365-mcp/server/no-cache.mjs) returns “not found” on load, ignores deletes and rejects saves with no file/keytar fallback. Graph's allowed scopes are User.Read Mail.Read Calendars.Read Contacts.Read Files.Read Tasks.Read MailboxSettings.Read Notes.Read. The allowlist restricts exposed tools, not permissions already granted to a supplied token. Logs use Ave's data directory with secret/PII redaction forced on.

## Targeted verification

Use the versions and cosign setup in the [README](../README.md#checks) and [workflow](../.github/workflows/validate.yml). The source-build check needs the pinned Bun version and read access to the public upstreams through gh. No provider account is authenticated by these checks.

~~~sh
node tools/connector-pins.mjs
node --test tools/__tests__/connectors-wave1.test.mjs
node tools/connector-build-check.mjs
node tools/connector-smoke.mjs
node tools/connector-smoke.mjs --opt-in trello-mcp todoist-mcp airtable-mcp obsidian-mcp figma-context-mcp google-workspace-mcp ms-365-mcp
node tools/release.mjs verify --base origin/main
node tools/index.mjs --check
node tools/vendor.mjs check
node tools/verified-import.mjs check --allow-development
node tools/check-retired-name.mjs
node --test tools/__tests__/tools.test.mjs
git diff --check
~~~

The [focused tests](../tools/__tests__/connectors-wave1.test.mjs) include the synthetic escaped-NUL reproducer, all ten credential boundaries, sanitized synchronous failures, minimal-PATH prerequisites, inventory/dependency tampering, and a real offline npm-ci negative control that changes transitive tarball bytes without changing its version. That control also proves lifecycle scripts stay disabled. The protocol check starts the real locked servers, compares their tool registrations, and directly calls every blocked tool. It repeats the relevant checks with both explicit write opt-ins enabled; Microsoft's auth tools remain unavailable. The connector CI job runs these checks on Linux and runs the two Python adapter tests in an environment installed from Google's hashed lock.

To run the Google adapter tests locally, create a Python 3.12.12 virtual environment, change to mcp/google-workspace-mcp/server, and use uv pip sync --python <venv>/bin/python --require-hashes --only-binary :all: requirements.lock before running <venv>/bin/python -B test_launch.py. Do not use an unlocked uvx environment for this test.

Generate the catalog only after the package commit exists. These additions are still unpublished, so the PR catalog replaces their earlier unmerged version pins with the repaired package commit; no main-published entry is changed or removed. When intentionally updating runtime code or dependencies, run node tools/connector-pins.mjs sync, inspect the changed inventories and lockfiles, then rerun the checks. CI status belongs to the PR. Protocol and credential-boundary checks establish startup, registration and rejection behavior; they do not prove provider login, token refresh or successful service API calls.
